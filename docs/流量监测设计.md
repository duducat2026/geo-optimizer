## 一、需求与决策

### 1.1 原始需求

1. 所有 example.com 子站点统一使用主站监测代码 **G-MAIN00000**，保证全站有一个总监控平台。
2. 子站点**周易大师**单独增加流量监测代码：
   - https://web.example.com
   - https://m.example.com
3. 子站点**星盘大师**单独增加流量监测代码：
   - https://astro.example.com
   - https://m.astro.example.com（需求原文 "m.astro.jexample.com" 为笔误，已按线上真实域名修正）

### 1.2 已确认决策

| 决策点 | 结论 |
|---|---|
| 主站直挂 gtag 的处理 | **同批迁移进 GTM**：摘除 abook 插件直挂的 gtag.js（全站唯一注入点），页面只挂容器，由容器标签统一投放 G-MAIN00000 |
| 全站汇总口径 | **先接受跨站会话不复合并**（各子域 client_id 不互通，汇总属性中同一用户跨站浏览计为多次会话）；报表口径命名为"汇总"，跨域 linker 留作二期 |
| 实现方式 | 页面只负责挂 GTM 容器 snippet；**所有 GA4 衡量 ID 的多投/分流全部在 GTM 容器内用「标签 + Page Hostname 触发器」实现**，未来增减监测点零代码改动 |

已固化的历史经验（本设计强制沿用）：

- **空容器断流教训**：摘除页面直挂 gtag 的前提是"容器内对应 GA4 标签已发布"，且必须拉取 `gtm.js` 正文核验标签实体存在，不能只看页面 snippet。
- **延迟注入教训**：任何动态/延迟注入 `gtm.js` 的代码，appendChild 之前必须 `dataLayer.push({'gtm.start': Date.now(), event: 'gtm.js'})`，否则 Initialization 触发器不激活。
- **验证判据**：以浏览器网络面板真实出现 `POST https://www.google-analytics.com/g/collect?tid=G-XXX…en=page_view`（204）为准；验证时带 `?cb=` 参数绕过浏览器磁盘缓存。
- **GTM 后台写法**：条件构建器 UI 存在 AngularJS digest 竞态，批量精确写入优先走同域内部 API（`/api/accounts/{acct}/containers/{cid}/workspaces/{ws}/tags|triggers`，带 `X-Xsrf-Token`）。

### 3.3 命名规范

- GTM 标签名 = 注册表"用途"列（如 `GA4-全站汇总`），GA4 属性/数据流同名前缀 `jcj-`，便于对账。

## 四、各站点执行清单

### 4.1 主站 www.example.com（WordPress 主站 / abook 插件）——需要改代码

**目标：摘除直挂 gtag，改为只挂 GTM-MAIN0001 容器，由"GA4-全站汇总"标签发 G-MAIN00000。**

改动点（**全站唯一注入点，1 处改动即全站全端生效**）：

- `wp-content/plugins/abook/includes/frontend/class-frontend-router.php`：改造 `inject_gtag()`（约 L64-80，挂 `wp_head` 优先级1）——删除 `<script async src="...gtag/js?id=G-MAIN00000">` 直挂脚本及配套 `gtag('config',...)` 内联块，替换为标准 GTM snippet；`abook_gtag_id` option 机制同步调整（改后页面不再持有 GA4 ID，ID 全部由容器统一管理）；
- 类构造函数中新增 `wp_body_open` 钩子（当前未挂），在 body 起始处输出 noscript iframe。

标准替换模板（同步 snippet，主站无首屏零依赖约束，直接 head 顶部）：

```html
<!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
})(window,document,'script','dataLayer','GTM-MAIN0001');</script>
<!-- End Google Tag Manager -->
```

body 起始处补 noscript iframe（`ns.html?id=GTM-MAIN0001`）。

**执行顺序强约束**：必须等「GA4-全站汇总」标签在容器版本4 **发布并正文核验通过之后**，才能上线摘除直挂 gtag 的版本，否则主站统计即时断流（历史教训重演）。建议顺序：容器版本4 先只含汇总标签+web/m 现有标签 → 核验 → 再发主站代码变更。

## 六、风险与注意事项

1. **顺序风险**：先发布容器标签、后摘页面直挂 gtag（4.1 ↔ 4.5 步骤7 的强约束），写反即断流。
2. **双投≠双重计数**：页面同时发"汇总ID+独立ID"两条 collect 是设计目标；同一 tid 发两遍才是事故（用 Hostname 例外触发器防）。
3. **汇总口径**：跨站会话不合并，全站 UV/会话为各站之和，报表须注明"汇总口径"；跨域 linker（`*.example.com`）列为二期。
4. **首屏约束**：jcjasp-frontend（loadThirdParty 延迟注入）与 web_home（零依赖+requestIdleCallback）的现有加载策略不动，任何重构不得省略 `gtm.start` push。
5. **部署脚本覆盖**：deploy-2 / deploy-3a 会整页下发 index.html，页面侧改动必须落在仓库源文件，不允许只改服务器。
6. **SPA 路由**：m.example.com/app/ 与 web 站的 hash/路由页二期再考虑 History/虚拟页面浏览触发器。
